# Jev Runner

横スクロールアクション。着地するたびに TypeSafe の **Jev（System One）** が直近の操作ログを見て
「腕前」「次の足場の種類」「イライラ度」「余裕度」を判定し、コードがそれを足場のジオメトリに変換する。
依存ゼロ（Node 18+ の `fetch` のみ）。

## 起動

```bash
node server.mjs
```

→ http://localhost:3210

API キーは環境変数 `TYPESAFE_API_KEY`、または `jev-runner/.env`（gitignore 済み）の
`TYPESAFE_API_KEY=...` から読む。キーはブラウザに一切渡らない（`server.mjs` が proxy）。
キーが無いとゲームは「heuristic モード」で動く（足場の色が灰色になる）。

疎通確認（モデル一覧 + 3 回の判定でレイテンシ表示）:

```bash
node probe.mjs
```

## 役割分担（typesafe-ai スキルの指針どおり）

| コードが所有 | Jev が判断 |
| --- | --- |
| 物理・到達可能性（`reach()`）・足場ジオメトリ | `skill`（score, 5 段階）: 直近 8 回の試行から腕前の期待値 |
| 難易度値の EMA と上下限、強制ルール（`frustrated > 0.75` → breather） | `next_platform`（choice, 7 種）: flow を保つ次の足場の種類 |
| 操作ログの数値 → 状況ラベル化（`well_timed`, `barely_made_it`, `long_pause`…） | `frustrated` / `cruising`（noul） |
| 先読みバッファ（2 枚先まで）とフォールバック | — |

4 問はすべて同じ state に対する独立した判断なので **1 リクエストにまとめて並列**で聞く。

## リアルタイム性の仕組み

- 着地 → 試行を記録 → 2 枚先の足場を Jev に問い合わせ（in-flight は常に 1 本）
- 応答（実測 ~550ms）が返るまでに現在の足場を渡り切ることはまず無いので、通常はプレイヤーが
  見る前に足場が確定する（シアンに発光している足場が Jev 製）
- 間に合わなかった場合はコードが `fallback`（オレンジ）を即生成し、遅れて届いた判定は難易度更新にだけ使う
- 落下時は「まだ画面外の一番遠い足場」を Jev に再判断させる（差し替え）

右パネルに毎リクエストのレイテンシ、score の確率分布、choice の確率分布、noul の値を表示する。

## 難易度の上下（合成ポリシー）

`applyJudgment()` が毎着地ごとに実行する。すべてコード側の明示ルール：

| 入力 | 効果 |
| --- | --- |
| `skill`（0〜4 期待値） | 目標値 `(skill − 0.5) / 3` に EMA(0.4) で追従。Jev は最上位レベルに確率を張り付けないので 3.5 で最大になるよう傾けてある |
| `frustrated > 0.6` | −0.15。`> 0.75` なら次は強制 breather |
| `cruising > 0.5` | +0.1 |
| 連続成功 6 回以上 | +0.01 × (streak − 5) × clamp(skill − 2.5, 0, 1)、最大 +0.1／着地。Jev がまだ「きれいに着地してる」と見ている間だけ効く。雑に生き延びているだけなら EMA の引き戻しが勝って下がる |

難易度 → 幾何は `mkPlatform()`。d=1 で間隔は到達距離の 90%、幅 36〜80px、移動足場は振幅 60px／周期 2s、壁は走行速度の 98%。
d > 0.6 からは複合ハザード（narrow が動く、long_jump/high_step/drop が細くなる、standard が動く）が確率 `(d − 0.6) × 1.6` で乗る。
足場ラベル末尾の `+` が複合の印。

## 調整ポイント

- `applyJudgment()`（`public/index.html`）: 難易度への合成ポリシー。ここだけ触れば挙動が変わる（Jev の質問は不変）
- `mkPlatform()`: 種類 × 難易度 → ジオメトリ。`reach()` × 0.88 で必ず到達可能に丸める
- `QUESTIONS`（`jev.mjs`）: 質問文・criteria。数字ではなく状況を書く（docs の指針）
